# Changelog

All notable changes are recorded here. The project follows [Semantic Versioning](https://semver.org); before 1.0, a minor version may change the API.

## Unreleased

- **Breaking:** `manifatura-models` is now `manifatura-providers`, re-exported as `manifatura::providers`; the facade feature `models-openai` is now `providers-openai` (still on by default). Types and functions keep their names (`Models`, `OpenAi`, `from_env`, `ProviderConfig`).
- `manifatura-providers`: `responses::Responses` (`responses` feature; `providers-responses` in the facade), a provider for OpenAI's Responses API: stateless, with encrypted reasoning sent back, tools optionally grouped in a namespace, and its bearer token from a key or from `Credentials`, a trait for tokens that refresh. It sends the request's `tool_choice`.
- **Breaking:** `ToolSpec` is `#[non_exhaustive]`: build one with `ToolSpec::new(name, description, input_schema)` or `ToolSpec::text(name, description, grammar)`.
- `manifatura-agent`: text tools. `ToolBuilder::run_text` makes a tool whose input the model writes as free text, optionally constrained by `ToolBuilder::grammar` (`Grammar::lark`, `Grammar::regex`). `ToolSpec::format` says how input is written (`ToolFormat::Json` or `ToolFormat::Text`); a text tool's schema is an object with one string field, `input` (`TEXT_INPUT`, `text_input_schema`), and its calls reach hooks as `{"input": text}`, so providers without free-form tools run it too.
- `manifatura-providers`: the Responses provider offers text tools as free-form `custom` tools with their grammar, at the top level beside a namespace, and reads and replays `custom_tool_call`s and their outputs.
- `manifatura-tools`: `apply_patch`, an alternative to `edit` in the patch format of OpenAI's Codex (`PATCH_GRAMMAR`): it adds, updates, moves and deletes files in one patch, finds each change by its context lines (exactly, then ignoring whitespace and typographic punctuation), and writes nothing unless the whole patch applies. It is a text tool, available through `by_name` and not in `all()`.
- `manifatura-agent`: more for commands in `Env`. `ExecSpec::tty` (a `TtySize`) runs a command in a terminal; `Process::take_input` hands out its input (`ProcessInput`) and `Process::interrupt` sends Ctrl-C (`SIGINT`; by default it kills). `Env::read_range` reads part of a file, so output is read a piece at a time where it is written. `ExecSpec::stderr` may name the same file as `stdout`. **Breaking** for code building `ExecSpec` without `..Default::default()`.
- `manifatura-tools`: `Local` merges stdout and stderr given one file, interrupts a command's whole process group, reads ranges by seeking, and runs commands in terminals with the new `pty` feature (on `portable-pty`).
- `manifatura-exec`, new, as `manifatura::exec` behind the `exec` feature (off by default; it turns on terminals for `Local`): `exec_command` and `write_stdin`, in the shapes of OpenAI's Codex. A command still running after its yield time keeps running under a session ID; `write_stdin` polls it, types into its terminal or interrupts it, and returns only new output, its beginning and end when long. `Exec::hooks` notes background exits for the model, and `Exec::subscribe`, `processes` and `kill` serve an app. Each session keeps 64 commands at most, and dropping the `Exec` kills them.
- `manifatura-agent`: `ExecSpec::unsandboxed` asks an env with a sandbox to run the command outside it; an env without one ignores it.
- `manifatura-sandbox`, new, as `manifatura::sandbox` behind the `sandbox` feature (off by default): `Sandbox`, an env wrapping another whose commands run under macOS Seatbelt. They read anything, write only to the workspace, the scratch directory and `/private/tmp` (never to `.git`, `.agents` or names given to `protect` at the top of the workspace), and have no network beyond ports and `localhost` (`network`, `writable` widen it). The env's own writes follow the same rules. Unsandboxed commands run only with `allow_unsandboxed`. On Linux, commands run under bubblewrap, in their own process and network namespaces (so `localhost` is the sandbox's own); `Sandbox::new` checks that `bwrap` can make a sandbox (user namespaces) and says why when it cannot.
- `manifatura-exec`: `Exec::escalation` adds Codex's `sandbox_permissions` and `justification` to `exec_command`, so the model can ask to run a command outside the sandbox; `is_escalation` picks those calls out for an approval hook, `ProcessInfo::escalated` marks them, and a sandboxed command that fails as a sandbox would make it fail gets a hint.
- `manifatura-kit`: `Approvals`, pending approval requests answerable from any client. A hook asks (`Approvals::ask`, or the `gate` bundle) and waits; clients follow `subscribe` (`ApprovalEvent::Requested`, `Answered`, `Cancelled`) or `pending` and answer by id, the first answer winning. A `Request` carries the session, the call, its scope, a reason and what "allow and remember" keeps; answers are recorded as custom `approval` records. `Answer` gains `AllowAndRemember` and `allows`, and is serialisable.
- `manifatura-policy`, new, as `manifatura::policy` behind the `policy` feature (off by default): allow, ask and deny rules for tools (`mcp__github__*`) and shell command prefixes (`exec_command(git commit)`), from code or a config file (`Rules`). Command lines are split with tree-sitter-bash into the simple commands they run (`policy::shell`); deny rules see inside substitutions, a line is allowed only when every command is allowed or read-only, and opaque lines never are. Defaults decide the rest (`when`, `tool_default`, `default`). `Policy::hooks` asks through `Approvals`, offering the rules that would allow the line next time, and `on_remember` hands remembered rules to the app.
- `manifatura-exec`: `Exec::types_into_escalated`, for a policy to ask before the model types into a command running outside the sandbox.
- `manifatura-agent`: `Effort` gains `XHigh`, `Max` and `Ultra` (the levels some OpenAI models have), `Effort::ALL` and `Effort::parse`.
- `manifatura-agent`: `Session::path`, the entries of the current branch, and `Session::history_so_far`, the current branch's messages as recorded, read without waiting for a turn in progress.
- `manifatura-snapshots`, new, as `manifatura::snapshots` behind the `snapshots` feature (off by default): a `TurnStart` hook that snapshots the working directory as each turn starts, as a git tree in a repository of its own, and records it in the session; `before` finds a message's snapshot, `Snapshots::changes` lists what differs and `Snapshots::restore` puts the files back. Git runs through the env.
- `manifatura-auth`, new, as `manifatura::auth` behind the `auth` feature (off by default): signing in to model vendors. `openai::SignIn` is OpenAI's Sign in with ChatGPT: dynamic client registration, a loopback callback on `127.0.0.1`, tokens in an owner-only file refreshed across processes under a lock, the plan's models, and a `Responses` provider on the user's plan. Each `Model` carries the plan's catalog: its `context_window`, `default_effort` and the `efforts` it accepts, with their descriptions. `examples/sign-in.rs` shows it.

## 0.3.0

- `manifatura-subagents`, new, as `manifatura::subagents` behind the `subagents` feature (off by default): a `task` tool that runs a subagent in a child session and returns its report. A subagent is an agent of its own or the calling session's agent with a brief (`Subagent::like_parent`), so it reuses the parent's prompt cache; it can also be written as Markdown (`Definition`). Approvals are shared both ways, nesting is limited (`max_depth`, 1 by default), aborting the parent aborts the child, and child events reach `action.log` and `Subagents::on_event`. `Subagents::run` starts a subagent from the app, as a task call would. `Subagent::tools` (or `tools:` in Markdown) limits the tools a child may call, keeping its prompt; `Subagent::max_steps` caps its model calls and keeps the last for its report.
- `manifatura-agent`: `ToolCx::agent`, the agent of the session a tool runs in, and `ToolCx::state_map`, every state key as the tool sees it; `Session::agent` and `Session::runtime`; `Agent::hooks_first`, for hooks that must decide before the others; `ModelRequest::tool_choice` (`ToolChoice::Auto` by default, or `ToolChoice::Off` for no tool calls), which `manifatura-models` sends as `tool_choice: "none"`. `ModelRequest` is `#[non_exhaustive]`: build one with `ModelRequest::new(model, messages)` and the setters `system`, `tools`, `max_tokens`, `reasoning` and `tool_choice`, so a call without tools never mentions them and later fields break no caller. Its fields stay public for providers and hooks.

## 0.2.0

- `manifatura-skills`, new, as `manifatura::skills` behind the `skills` feature (on by default): Agent Skills. Skills are found in `.agents/skills` (project and home), other directories and built into the app, with project skills taking precedence; `SystemPrompt::skills` (from `SystemPromptExt`) lists them in the prompt, the `skill` tool loads one, and `SkillSet::activation` serves `/name` commands.
- `manifatura`: `prelude`, the names most programs use, following the features.
- `manifatura-agent`: `ToolBuilder::keep_results` marks a tool whose results stay relevant for the rest of the task (`Tool::keeps_results`, `Tool::with_keep_results`).
- `manifatura-kit`: `compaction::trim_results` leaves the results of such tools whole. `SystemPrompt::section` ignores empty text.

## 0.1.0

The first release.

- `manifatura-agent`: the loop, fifteen typed hook points, sessions as an append-only tree with branching and compaction, steering and follow-ups, and the `Provider`, `Env` and `Store` traits.
- `manifatura-kit`: approvals with scoped "always" answers, compaction hooks and a summariser, a deferred tool catalog, input repair, `AGENTS.md` discovery, a system prompt built from tool guidelines, and the system delta for warm prompt caches.
- `manifatura-models`: llama.cpp and any other OpenAI-compatible server behind a `provider/model-id` registry.
- `manifatura-store`: sessions as JSON lines, repaired after a crash mid-write.
- `manifatura-tools`: `read`, `edit` (which also creates files), `grep` and `glob` (respecting `.gitignore`), and `bash` with background jobs; `Local`; script tools.
- `manifatura-mcp`: MCP servers' tools, over stdio or streamable HTTP.
- `manifatura`: the facade, with each block behind a feature.
